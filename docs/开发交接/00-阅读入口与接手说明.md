# 小红书 AI 运营助手开发交接

整理日期：2026-11-06。面向接手开发的 AI 和开发者。

这是一份改造计划，不代表以下功能已经实现。用户已认可产品方向，本次交付仅为开发文档；实施时先检查最新代码和本机运行状态，避免把计划当成现状。

## 已确定的产品方向

用户通过 Codex、WorkBuddy 等 AI 工具生成文案和图片，将内容保存到本地指定账号，安排定时发布，并查看数据。Obsidian 不再作为主要入口，保留兼容。保留本地管理网页，用于扫码、预览、编辑、筛选、排期和排障。

第一版交付完整路径：安装 → 接入 AI → 添加账号并扫码 → 生成并保存草稿 → 预览修改 → 明确安排发布 → 后台执行 → 查询结果和数据。

## 阅读顺序

1. `01-产品范围与架构.md`：产品边界、当前程序和目标结构。
2. `02-分阶段开发任务.md`：按依赖实施的工作包和阶段出口。
3. `03-接口数据与状态约定.md`：草稿、账号、任务、MCP 和状态约定。
4. `04-安装更新与验收.md`：分发、数据迁移、后台服务、验证和交付。

## 当前程序入口

- 启动：`./venv/bin/python run.py`。
- 本地网页：`http://127.0.0.1:8643/`。
- 技术：Python、FastAPI、SQLAlchemy/SQLite、APScheduler、Patchright、Vue 3 静态页面。
- 测试：`./venv/bin/python -m unittest discover -s tests -v`。
- 数据：当前位于 `data/`，含真实数据库、上传素材和账号浏览器环境。
- 现有文档：项目根目录 `README.md`、`tests/TEST_REPORT.md`；后者是历史报告，不代表新改造的验收结果。

## 接手要求

- 先核对代码、测试、任务和数据库版本，再开始修改；不要仅依赖聊天里的“已修复”。
- 不删除真实账号、素材或笔记，不用真实账号自动发布测试内容。
- 所有测试使用临时数据目录。真实扫码、真实发布测试须明确纳入用户授权范围。
- 保留已验证的国内/海外域名兼容、独立账号环境、缩略图、中文时间、账号与状态组合筛选、前端脚本版本机制。
- 不提交或打包 `venv/`、`data/`、真实 Cookie、代理密码、用户生成的图片和日志。
- 按阶段提交可运行成果；每阶段报告变更、验证、迁移影响和剩余限制。
- 对发布结果不明的任务先对账，不自动重发。

## 可直接发给接手 AI 的任务说明

> 请阅读 `docs/开发交接/` 下全部文档，检查现有代码和测试，按 `02-分阶段开发任务.md` 顺序改造本项目。先完成 P0 基线与数据保护、P1 草稿和可靠任务，不要直接重写全项目。首版采用现有 Python 核心、本地常驻服务、MCP 和 Skill 接入，保留网页。所有内容默认保存草稿，只有明确安排发布才执行。每篇笔记必须绑定 account_id。支持国内小红书和海外 rednote，不能混用账号凭据。不要用真实账号做未经授权的发布测试。未实现的功能不得标为完成；每阶段提供验收结果和迁移说明。
