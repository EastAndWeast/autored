# 接口数据与状态约定

本文是目标接口契约，现有 API 未实现此契约。字段名称可在实施时统一调整，但不得改变“草稿与发布分离、显式账号、持久任务、发布幂等”的行为。

## 账号

保留 Account 主键和独立 profile；补充 platform_region（unknown/cn/global）、creator_base、platform_user_id、platform_nickname、timezone 和可选 writing_preferences。

- 默认平台 unknown，扫码重定向和平台身份核验后记录实际区域。
- 国内基址 `https://creator.xiaohongshu.com`；海外基址 `https://creator.rednote.com`。
- 当前 creator_base 根据 Cookie 推断且优先海外；两域都有旧凭据时可能有歧义。目标应优先使用已核实的账号平台和平台身份，Cookie 作为辅助，不复制凭据跨域。
- 显示“备注名 + 平台昵称 + 国内/海外”，避免本地名称与后台昵称不同造成误认。
- 登录状态包括未登录、登录中、在线、已失效；网络失败单独记录检测结果，不直接等同已失效。
- 时区是账号排期的显式属性，不能因为海外账号就自动猜海外时区。首版默认 Asia/Shanghai，可配置。

## 笔记与修订

保留 Note，逐步补充 revision、source、created_by、submitted_at、confirmed_at、platform_status、verification_status 和媒体引用。记录发布时使用的内容快照/修订，避免等待中的任务悄悄发布后来修改的内容。

草稿允许标题或媒体未齐全；publish-ready 校验在排期时及真正执行前进行，返回缺失字段。草稿有效性与可发布性分开。首版可继续使用现有字段作为显示投影，但迁移规则必须明确。

账号改名不影响 account_id。仅草稿可显式变更账号，迁移归属与素材引用保持原子性；已排期先取消，已经提交平台后不允许转移归属。

## 任务和尝试

新增 PublishJob，建议至少包含：

- id、note_id、account_id、note_revision、内容快照引用。
- mode（immediate/local/platform）、requested_at、scheduled_for_utc、timezone。
- effective_at：受限流等影响的实际最早执行时间；与用户原始时间分开。
- status、idempotency_key、payload_hash、attempt_count、lease_owner、lease_expires_at。
- cancel_requested、last_error_code、last_error_message、created_at、updated_at。

新增 PublishAttempt，记录开始/结束、平台域名、提交阶段、脱敏响应摘要、平台 ID、成功页 URL、真实详情 URL 和核对结果。不保存 Cookie/授权请求体到日志。

数据库唯一约束至少覆盖幂等键作用域；同一个笔记修订只允许一个有效发布任务。数据库事务完成后调度器才能执行。内存队列只能用于唤醒，不能作为任务唯一记录。

## 状态机

| 状态 | 中文展示 | 判据及后续 |
|---|---|---|
| draft | 草稿 | 保存完成，不可自动执行 |
| scheduled | 等待定时发布 | 有明确发布时间和有效任务 |
| queued | 排队中 | 到期或立即任务，等待锁/频控 |
| publishing | 发布中 | worker 已持有任务租约 |
| platform_scheduled | 已提交平台定时 | 平台确认接收定时，保留平台计划 |
| submitted | 已提交，等待确认 | 已取得提交证据，尚未核对内容记录 |
| verifying | 待核对 | 提交结果不明或崩溃恢复，禁止盲目重发 |
| published | 已确认发布 | 平台内容记录确认发布，保存证据 |
| failed | 发布失败 | 有明确失败证据，可在检查后重试 |
| cancelled | 已取消 | 确认尚未产生平台提交，或平台取消已确认 |
| needs_login | 需要重新登录 | 明确登录失效，任务暂停 |
| overdue | 已逾期，等待处理 | 本地错过排期，由用户选择重排或发布 |

这些是业务语义，不要求所有状态都塞入 Note.status。建议任务状态为权威，笔记保存汇总状态，避免两套状态独立漂移。

平台“审核中、未通过、已发布”等另存 platform_status，不能将审核中当作提交失败。平台内容记录存在，也不等同已验证手机端或公开访问可见。

取消规则：未提交任务可取消；已提交平台定时必须执行平台取消并核实，若暂不支持则返回 unsupported，并提示到平台操作；删除本地记录不能宣称已撤销平台内容。提交中取消请求与平台结果需对账。

崩溃规则：尚未点击提交的可恢复执行；可能已经提交的转 verifying。不能保证跨第三方平台严格 exactly-once，但必须通过幂等、证据和对账避免盲目重复。

## 建议 HTTP 与 MCP 能力

建议新接口使用 `/api/v1`，旧接口短期保留适配，标明兼容期限。新工具绝不把现有“创建即发布”的接口当草稿接口。

| MCP 工具建议名 | HTTP 建议 | 行为 |
|---|---|---|
| list_accounts | GET /api/v1/accounts | 返回稳定 ID、昵称、区域、状态 |
| start_login | POST /api/v1/accounts/{id}/login | 返回登录任务和本地操作地址，扫码由用户完成 |
| get_login_task | GET /api/v1/login-tasks/{id} | waiting/scanning/verifying/success/failed |
| create_draft | POST /api/v1/drafts | 显式 account_id，默认仅保存 |
| update_draft | PATCH /api/v1/drafts/{id} | 携带 expected_revision，防并发覆盖 |
| import_media | POST /api/v1/media | 导入后返回服务托管 media_id |
| list_notes | GET /api/v1/notes | 支持 account_id/status/分页 |
| get_note | GET /api/v1/notes/{id} | 草稿、归属、素材、最新任务和证据 |
| schedule_publish | POST /api/v1/notes/{id}/publish-jobs | 校验修订、内容、时间；返回任务 |
| get_publish_job | GET /api/v1/publish-jobs/{id} | 状态、等待原因、后续动作 |
| cancel_publish_job | POST /api/v1/publish-jobs/{id}/cancel | 按当前提交阶段判断能否取消 |
| refresh_stats | POST /api/v1/accounts/{id}/stats-jobs | 异步采集，立即返回任务 ID |
| get_stats | GET /api/v1/stats | 账号/笔记/时间范围、快照与采集状态 |
| get_runtime_status | GET /api/v1/runtime | 版本、服务状态、队列、浏览器可用性 |

创建草稿示例：

```json
{
  "account_id": 1,
  "title": "周末美食节逛吃计划",
  "content": "正文……",
  "tags": ["美食节"],
  "media_ids": [],
  "source": "codex",
  "idempotency_key": "由调用方生成的唯一请求标识"
}
```

安排发布示例：

```json
{
  "note_revision": 3,
  "mode": "schedule",
  "scheduled_at": "2026-11-20T19:00:00+08:00",
  "timezone": "Asia/Shanghai",
  "idempotency_key": "另一唯一请求标识"
}
```

时间必须带 offset，同时验证与指定 timezone 一致；数据库以 UTC 存储，界面按账号时区展示。立即发布使用 mode=immediate，不伪装成空 scheduled_at 的编辑操作。用户请求时间与调度调整分开保存；若保留随机抖动，应在预览显示实际执行窗口，不能静默修改用户排期。

幂等规则：相同 key、相同 payload 返回原结果；相同 key、不同 payload 返回冲突；适用于草稿和发布任务。并发请求通过数据库约束处理，不只靠进程内锁。

返回包含 resource_id、status、version/revision、request_id 和可操作的 next_action。MCP 按标准返回结构化数据，HTTP 可使用 202 表示已受理。耗时浏览器任务不阻塞请求；网络请求应有超时、忙碌和重试信息。

错误码建议：ACCOUNT_NOT_FOUND、AMBIGUOUS_ACCOUNT、LOGIN_REQUIRED、NETWORK_TIMEOUT、MEDIA_MISSING、REVISION_CONFLICT、IDEMPOTENCY_CONFLICT、JOB_BUSY、RESULT_UNCERTAIN、UNSUPPORTED_OPERATION。

## 素材和访问边界

- 素材必须复制进服务管理目录再返回成功，宿主临时文件删除后仍可发布。
- MCP 与后台必须能访问同一文件或使用明确上传传输，不能假设宿主沙箱路径就是后台本机路径。
- 校验文件头、大小和类型；拒绝路径穿越、任意绝对路径读取和不受控远程 URL 下载。
- stdio 适配器和本地 HTTP 连接使用当前用户可读的本地凭据，继续保留 Host/Origin 防护，不为接入 MCP 直接关闭现有防护。
- 账号 Cookie 不通过 MCP 返回。导出素材和诊断包不含浏览器 profile、代理密码和授权信息。
