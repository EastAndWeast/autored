# 安装更新与验收

## 发行策略

先完成一个系统的闭环，其他系统代码保持可移植但不标为支持。首发系统等待产品负责人确认。开发环境已有 Python、浏览器和本机数据，不等于新用户能安装。

每个发行版本包含：程序安装包、本机运行时、依赖锁定清单、兼容浏览器版本说明、两类宿主接入包、安装/升级/回退文档、版本与校验信息。不要直接把整个项目目录或 venv 压缩给用户。

建议核心保持 Python；安装器方案通过小型验证选择能够打包运行时、启动浏览器和管理用户级服务的工具，工具选择不应阻塞业务重构。macOS/Windows 的签名和平台告警需真实测试；证书和发布身份由负责人提供。

## 安装体验

1. 下载页按系统和架构提供明确版本、大小、更新说明、校验信息与卸载说明。
2. 安装程序到程序目录；初始化独立用户数据目录，不要求写入安装目录。
3. 检查运行时、浏览器组件、目录权限、端口和已有服务实例。
4. 浏览器组件下载有进度、校验、超时和重试；是否支持断点续传取决于实现，未验证不得宣称支持。无需每次调用工具重新下载。
5. 提供启动后台、打开管理页、查看诊断和停止后台的简单入口。
6. 引导选择 Codex/WorkBuddy，通过其受支持方式安装接入配置；更改用户已有配置前备份并合并，不能覆盖其他 MCP。
7. 添加账号并扫码，完成关闭重开验证，创建草稿进行验收。

首版不承诺已进入任何官方市场。WorkBuddy 的连接器方案与元信息、Codex 的 MCP/Skill 配置应依据各自最新官方文档实现。接入包只是入口，不能把后台是否安装、是否运行交给用户猜。

## 后台运行

- 用户级单实例服务：macOS 可评估 LaunchAgent；Windows 可评估当前用户登录启动/任务计划。避免不必要的管理员权限。
- 账户锁需要跨进程有效，现有 threading.Lock 不能防止两个独立后台进程争抢同一 profile。
- 命令建议：`start`、`stop`、`status`、`doctor`、`open`、`update`；名称待产品命名后确定。
- stdio MCP 适配器不拥有发布 worker 生命周期；两个宿主只能连同一后台。
- 运行诊断显示服务版本、数据路径、浏览器版本、待处理任务、最近错误和端口。拒绝不兼容宿主/核心版本并给出修复指引。
- 网页关闭不会停止后台；电脑关机或休眠仍会影响本地发布和采集。界面明确提示条件。
- 冷却、限流和队列等待要可见。服务健康不等于登录有效或平台可访问。

## 数据迁移

1. 发布前暂停新任务并检查正在提交的平台操作。
2. 一致性备份 SQLite；停止 browser context 后再迁移 profile。
3. 记录旧目录、目标目录、schema 版本、应用版本及迁移阶段。
4. 拷贝素材/profile，校验文件数量和引用完整性；保留原副本直至迁移确认。
5. 迁移 SQLite，保留主键及关系；修正相对路径，不硬编码本机用户名。
6. 测试样本草稿、图片访问和账号恢复，确认任务没有重复恢复。
7. 原有已发布记录不得因新状态机迁移被自动排入队列。

默认数据目录选择操作系统标准用户数据位置，支持可配置覆盖；选定后在文档写明。不要同时创建多个看似独立的数据目录导致“账号不见了”。

## 更新与回退

- 核心、MCP 适配器和 Skill 各有版本与兼容范围，用户界面显示整体发行版本。
- 首版建议“检测更新 → 提示 → 安装”，不在发布中途静默替换核心或浏览器。
- 发行清单含版本、系统、架构、下载地址、校验及兼容信息；通过受信任渠道获取并验证完整性/发布来源。
- 先下载到暂存目录，校验成功，再停服务、备份、迁移、原子切换、健康检查，完成后恢复任务。
- 发布结果不明的任务进入核对；升级不能触发自动重复发布。
- 回退同时考虑二进制和数据库 schema；旧程序不支持新 schema 时禁止直接降级。需要恢复备份时，必须对迁移后新产生的数据给出保留/导出方案，不能静默丢弃。
- 卸载默认保留用户内容和凭据目录；彻底删除作为另一个明确动作。不要卸载其他软件共用的浏览器组件。
- 导出内容与完整备份分开；完整登录环境备份属于敏感数据，不进入普通诊断包。

## 验收矩阵

| 场景 | 通过标准 |
|---|---|
| 无 Python 的干净系统 | 按安装步骤可启动和连接宿主 |
| AI 保存文字草稿 | 无媒体也保存，且始终不触发发布 |
| AI 临时图片导入 | 删除宿主临时文件后素材仍能预览和使用 |
| 账号改名 | 原笔记归属不变，筛选正确 |
| 国内与海外账号 | 登录、重开、发布入口和采集分别验证，无凭据混用 |
| 请求重放和并发 | 同幂等键同 payload 返回原资源，不重复发布 |
| 修改已有排期内容 | 通过修订冲突或显式重排防止内容错配 |
| 点击提交后崩溃 | 恢复进入待核对，不直接重发 |
| 平台定时到点 | 不凭时间自动宣称已发布 |
| 平台审核中或延迟 | 显示真实状态，不误判失败、催促重发 |
| 后台冷却与刷新 | 返回等待原因，HTTP/MCP 请求不挂起 |
| 关闭网页和 AI | 后台任务仍执行，无第二个 worker |
| 电脑休眠错过排期 | 恢复后暂停并提示，由用户选择处理 |
| 网络超时 | 区别网络失败和登录失效，保留诊断 |
| 数据尚未生成 | 显示未采集/不可用和时间，不用 0 冒充成功 |
| 页面升级 | 旧缓存不会导致新模板函数缺失、页面空白 |
| 旧版升级 | 内容、素材、账号、任务引用保留，可恢复 |
| 多宿主连接 | 复用后台及账号锁，无重复调度 |
| 卸载与重新安装 | 按保留策略恢复数据，不意外清空 |

## 验证纪律

基础命令：`./venv/bin/python -m unittest discover -s tests -v`。接手后改为可移植路径和临时环境，补充领域测试、迁移测试、故障注入和浏览器界面检查。

真实平台验证分开记录账号区域、时间、版本、操作和证据；仅使用用户明确授权的内容进行真实发布，不批量造测试笔记。国内、海外不能相互替代验收。统计采集须有真实记录对账，只有接口 HTTP 200 不算通过。

交付时附：版本、变更清单、安装包、宿主接入包、测试报告、迁移/回退说明、已知问题、数据位置、运行条件、卸载说明。不得把本次计划文档当成验收通过报告。
