# 产品范围与架构

## 首版用户能力

1. 添加多个账号，扫码登录，显示账号备注名、平台昵称、平台区域和登录状态。
2. 在 AI 工具里提出创作要求，生成标题、正文、话题及可用配图。
3. 将草稿、素材归入明确的本地账号；账号改名不影响归属。
4. 预览、改写、保存，不默认发布；媒体未准备好也可保存草稿。
5. 立即发布或指定时间发布，可查询和取消尚未提交平台的计划。
6. 关闭聊天窗口和管理网页后，常驻后台仍执行任务。
7. 查看提交、平台确认和数据采集结果；遇到登录失效给出操作入口。
8. 普通用户无需自行安装 Python、建立虚拟环境或执行浏览器安装命令。

## 首版范围之外

不做云端代管账号、多人协作权限系统、全平台内容分发、全天候自动选题生成、承诺精准到秒发布、强制接入 Obsidian，以及自建模型聊天产品。暂不重写为 Electron/Tauri 大型桌面客户端；先采用轻量安装器、服务管理入口和现有网页。

AI 写作优先使用宿主能力；若宿主没有图像生成能力，支持上传图片，或只保存文字草稿并标记缺少媒体。MCP 不提供宿主未具备的生图能力。没有真实素材时，不能编造探店经历、日期、地址、价格或优惠。

## 现有代码映射与已知缺口

| 文件 | 当前职责 | 改造重点 |
|---|---|---|
| `run.py`、`app/main.py` | HTTP 服务、静态页面、启动调度 | 启动入口、版本和运行状态、独立常驻生命周期 |
| `app/config.py` | 路径及全局参数 | 用户数据目录、安装目录分离、时区配置 |
| `app/models.py` | 账号、笔记、统计、日志和设置 | 数据库迁移、持久任务、账号平台信息、发布证据 |
| `app/api/notes.py` | 创建、编辑、立即发布、上传 | 独立草稿接口、显式调度、媒体管理、幂等 |
| `app/api/accounts.py` | 账号 CRUD、扫码、检测 | 账号身份、平台归属、检测异常与失效分开 |
| `app/scheduler.py` | 扫描、内存队列、worker、采集 | 持久任务、冷却时间、崩溃恢复、平台对账 |
| `app/xhs/browser.py` | 浏览器环境与域名识别 | 继续隔离，域名显式持久化及自动校正 |
| `app/xhs/login.py` | 登录、保存与重开校验 | 保留验证，防超时误判，异步任务反馈 |
| `app/xhs/publisher.py` | 上传、填写、提交 | 获取平台 ID/链接、提交证据和不确定结果 |
| `app/xhs/stats_collector.py` | 平台数据读取 | 国内海外分别验证，空数据原因和采集时间 |
| `app/web/` | Vue 管理页面 | 草稿、任务、账号、时间、状态和错误展示 |
| `app/obsidian_sync.py` | 导入 Markdown | 保持可用，降为可选入口 |

具体问题：当前创建笔记直接设为 pending；编辑 scheduled_at 也会改为 pending；内存队列不是持久任务记录；重启时 publishing 被放回 pending 有重复发布风险；到期平台定时直接改 published 缺少平台证据；成功页可能没有 note_id，不能当成笔记详情链接；数据采集曾返回 0 条，数据闭环还需实际验证。原有限流会在 worker 内休眠 5–15 分钟，可能连带延迟数据刷新。

## 推荐目标结构

```text
Codex / WorkBuddy
  ├─ Skill：创作、改写、账号选择、工作流说明
  └─ MCP 工具适配器
          ↓
本地唯一后台进程
  ├─ 应用服务：账号、草稿、素材、排期、数据
  ├─ FastAPI 与管理网页
  ├─ 持久任务与调度
  ├─ 国内 / 海外平台适配
  └─ SQLite、素材文件、私有浏览器环境
```

提取公共应用服务层，例如 `app/services/`；HTTP、CLI、MCP 均调用公共业务逻辑，避免三套独立校验。CLI 用于安装、启动、诊断及运维，命令只是产品方案，尚不存在。

MCP 推荐先用 stdio 适配器连接本地常驻服务。宿主关闭时可结束适配器，但不能结束发布后台；多个宿主连接同一后台，不得分别启动 worker。若改用本地 HTTP MCP，需提供认证、生命周期和宿主兼容验证。

常驻服务即使正常运行，也不能在电脑关机或休眠时执行浏览器任务。官方定时在平台确认接收后可由平台执行；本地任务需提示电脑运行条件和逾期处理。

## 本地数据

SQLite 是账号归属、笔记和任务状态的唯一权威；文件夹是素材存储和可读导出，不允许两边独立修改状态后互相覆盖。

```text
用户数据目录/
  database/app.db
  accounts/account_<id>/notes/<note-id>/
    content.json
    文案.txt
    media/
  private/profiles/account_<id>/
  logs/
  backups/
  runtime/
```

用稳定 ID 作为路径，不用备注名；导出不含凭据。content.json 和文案.txt 默认是可重建导出，不承担自动双向导入。支持“打开账号素材目录”和整篇导出。

旧数据迁移要保留账号 ID、笔记 ID、媒体引用及完整浏览器 profile；迁移登录环境后必须实测可用，不能只搬数据库。安装与用户数据分别选用各操作系统标准位置，支持明确的数据目录覆盖。
